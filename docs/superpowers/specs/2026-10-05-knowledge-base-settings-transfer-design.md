# 知识库设置、检索参数与完整导入导出设计

**日期：** 2026-10-05  
**状态：** 已实现并完成验证

## 目标

补齐知识库级设置修改、检索参数保存、全量重建以及完整导入导出能力。完整包包含知识库设置、检索参数、文档元数据和原始文件；导入默认创建新知识库，不覆盖现有数据。

## 现状与边界

- 已有知识库创建、列表、详情和删除接口，但缺少编辑接口。
- 已有检索接口支持 `mode`、`top_k`、`score_threshold`、语义/关键词权重和重排开关，但这些参数没有知识库级持久化设置入口。
- 已有文档级重新索引和索引配置任务，缺少知识库级一键全量重建。
- 已有单文档上传/下载，但没有包含元数据和原始文件的知识库归档包。
- 不导出向量、已生成分段、任务内部 ID、对象存储凭据或其他运行时秘密；导入后文档统一进入 `waiting`，由当前配置重新索引。

## 设计

### 持久化与 API

`DatasetRecord.retrieval_model_config` 保存知识库级检索参数，`partial_user_config` 保存可导出的索引/处理配置摘要。新增设置 DTO 和服务方法，在更新时校验字段范围、权重和模式，并更新 `updated_at`。

新增接口：

| 方法 | 路径 | 行为 |
|---|---|---|
| GET | `/api/knowledge_base/{dataset_id}/settings` | 返回基本设置、索引设置和检索参数 |
| PATCH | `/api/knowledge_base/{dataset_id}/settings` | 保存设置；索引相关变更标记需要重建 |
| POST | `/api/knowledge_base/{dataset_id}/rebuild` | 创建全量重建任务并在提交后投递 |
| GET | `/api/knowledge_base/{dataset_id}/export` | 流式返回完整 ZIP |
| POST | `/api/knowledge_base/import` | 校验 ZIP 并创建新知识库和文档 |

重建沿用 `ProcessRuleService`/`IndexingRepository` 的任务和发布边界，任务提交成功后才向 Celery 发布消息；重复的在途全量任务返回现有任务而不重复创建。

### 归档包

ZIP 根目录包含：

```text
manifest.json
dataset.json
retrieval.json
documents.json
files/<document-id>/<safe-filename>
```

`manifest.json` 包含格式版本、导出时间、原知识库 ID、文档数量及文件 SHA-256。`dataset.json` 保存名称、描述、权限、分类、索引方式和 Embedding 配置。`retrieval.json` 保存检索参数。`documents.json` 保存文档 ID、名称、启用/归档状态、来源信息、大小、内容类型、哈希和相对文件路径。

导出使用临时文件或流式 ZIP 写入，逐个从对象存储读取，不能把整个知识库文件内容加载到内存。导入先读取并校验 ZIP 中央目录和 manifest，拒绝绝对路径、`..` 路径、未知必需文件、成员数量/单文件/总大小超限以及哈希不匹配。原始文件先写入临时对象键，数据库事务成功后再把对象键切换到新知识库前缀；事务失败时清理已写入对象。

导入创建新的 UUID 知识库和新的文档 UUID，保留原 ID 作为 `data_source_info.imported_document_id` 审计字段。所有导入文档状态为 `waiting`，导入接口可通过 `rebuild` 参数决定是否提交全量重建任务。

### 前端

在文档页增加知识库设置面板，包含基本设置、检索参数、索引与重建、导入导出四个区块。保存设置后刷新父页面数据；重建需要二次确认并显示任务状态；导出触发浏览器下载；导入显示校验/创建结果和自动重建结果。已有文档级索引配置和文档级重建继续保留。

## 错误处理

- 知识库不存在：404。
- 设置字段或检索参数越界：422。
- ZIP 格式、路径、大小、数量或哈希错误：422，返回稳定的用户可读错误，不暴露内部路径和凭据。
- 数据库、对象存储或消息队列暂时不可用：503。
- 导入数据库提交失败：删除本次已写入的临时对象并回滚，不留下可见的半成品知识库。

## 已知难点

1. **ZIP 与 MinIO 的流式边界**：`zipfile` 需要可 seek 的输出，而对象存储只提供异步流；采用受限临时文件作为 ZIP 构建缓冲，单文件读取仍按块进行，避免把完整知识库驻留内存。
2. **数据库与对象存储没有跨系统事务**：导入采用“对象临时前缀 + 数据库事务 + 失败清理”，并让文档只有在事务提交后才可见。
3. **历史配置兼容**：旧知识库的检索配置可能是 `NULL` 或缺字段，服务返回稳定默认值，保存时只写允许的白名单字段。
4. **全量重建与现有单文档任务边界**：全量重建必须创建新的索引版本并在成功后切换，不能复用单文档兼容任务造成局部/全量语义混淆。
5. **导入后的索引状态**：导入包不能假装携带可用向量，所有文档从 `waiting` 开始；自动重建发布失败时保留文档并返回待投递状态。
